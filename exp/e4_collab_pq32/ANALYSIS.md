# E4 — PQ32 路线：协同 / 算力 / 链路计费 与"不带计算节点的 CXL SSD"基线

## E4-B1 — CXL 每次访问计费（本次核心）

### 动机：仿真保真度缺口
首轮实测：纯 CPU 读器件窗口 **299.2 ms/查询** vs 器件内执行 **275.9 ms/查询**——只差 8.4%。
这与"近存计算"该有的量级不符。根因：**FEMU 的 DER 模型只对填充/重陷计费（NAND 40µs），
EPT 翻转后 guest 的读是本地内存读**；真实 CXL 上 CPU 每访问一次都要过链路
（往返 ~100-300ns + 带宽），这笔账此前完全没计。

### 旋钮设计
客户端 CLI 旗标（不是 host `/tmp` 文件——计费点在 guest 内）：
- `--cxl-access-ns=N`：每次窗口访问的链路代价，**默认 0 = 关闭 = 与既有全部结果逐位相同**
- `--cxl-mlp=M`：访存并行度（计费按 N/M），默认 1
- 计费对象：**仅 guest 发起的访问**（`n_dist` 码读 + `n_hops` 邻接读 + `R` 重排向量读
  = **95,492.3/查询**，与预测逐位一致）；**引擎臂不计**（器件内部访问不跨链路）
- 结算：每查询末尾忙等；**纯时间、不动数据路径** ⇒ 门禁 md5 必须保持

### 结果（全部 n=1000, ef=R=2048, PQ32）
| 臂 | c(ns/访问) | MLP | p50 | exec | 门禁 md5 | 模型计费 vs 实测 Δ |
|---|---|---|---|---|---|---|
| cpu_c0 | 0 | 1 | 297.5 ms | 3003.2 ms→**300.3** | d8986bce ✓ | — |
| cpu_c300 | 300 | 1 | 327.3 | **329.4** | ✓ | 28.6 vs 29.1 (+1.7%) |
| cpu_c1000 | 1000 | 1 | 393.3 | **396.2** | ✓ | 95.5 vs 95.9 (+0.4%) |
| cpu_c3000 | 3000 | 1 | 586.4 | **587.8** | ✓ | 286.5 vs 287.5 (+0.4%) |
| cpu_c3000_m8 | 3000 | 8 | 336.1 | **338.2** | ✓ | 35.8 vs 37.9 (+5.7%) |
| **eng_f0（器件执行）** | — | — | 278.7 | **276.6** | ✓ | 不计费 |

（exec 单位 ms/查询；7/7 臂 md5 = `d8986bceca1755465b2119b422ed9b07`，recall 恒 0.9458）

**计费加性精确**：实测 Δexec 与模型 `95,492 × c / MLP` 在 0.4-5.7% 内闭合（与 E2 旋钮扫描同法验证）。

### 结论：近存计算值多少？
| 每次访问链路代价 | CPU 臂 | 引擎臂 | 引擎优势 |
|---|---|---|---|
| 0 ns（= 仿真此前的隐含假设） | 300.3 ms | 276.6 ms | **+8.6%** |
| 300 ns（真实 CXL 往返，同步） | 329.4 ms | 276.6 ms | **+19.1%** |
| 1000 ns（链路拥塞） | 396.2 ms | 276.6 ms | **+43.2%** |
| 3000 ns（极端） | 587.8 ms | 276.6 ms | **+112.5%** |
| 3000 ns 但 8 路访存重叠 | 338.2 ms | 276.6 ms | +22.3% |

1. **诚实地把链路计上后，器件内执行的延迟优势是 19%（真实 CXL）到 43%（拥塞链路）**——
   真实、可辩护，但**不是数量级优势**。此前"8.4%"是无计费假设下的产物，不作数。
2. **上限被共同成本锁死**：两侧都付同一笔设备 NAND miss 账（misses 4,425/查询 × ~38µs
   ≈ **168 ms**，占引擎 276.6 ms 的 61%）。加速器省掉的是链路 + 陷阱 + 卸载，
   省不掉介质本身——所以优势上限由"非 miss 部分"决定。
3. **访存重叠（MLP）能吃掉大部分链路账**：8 路重叠下 3000ns 的计费从 +287ms 降到 +38ms。
   即：**一个会做异步/预取的 CPU 实现，能把这条曲线压平**——这也是我们对 CPU 阵营的
   公平性注记（我们的客户端是同步的，属悲观侧）。
4. **因此加速器的价值主张仍是结构性的**：解放宿主 CPU（器件干活时宿主空闲）、
   索引不占宿主 DRAM（容量）、以及多 job 流水线的潜力（未测，A1 待办）——
   而不是"延迟快 N 倍"。

### 口径纪律（沿用并新增）
- 1.91×（全驻留协同，A0 路线）与 41×（容量受限，E3）不可混引
- **CXL 论证用"数据不动"**，不说"accelerator 取数更快"
- **新增**：引用本表时必须写明 `c` 与 `MLP`；`c=0` 那一行是"无链路计费"假设下的数字，
  真实硬件对应 `c≈100-300ns`（同步）或更低（有重叠）
